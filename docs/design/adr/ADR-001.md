# ADR-001: Adopt Modular Monolith Architecture with Django MVT and Server-Side Rendering

- Status: accepted

## Context
The SmartLib Booking system should be designed, implemented, and tested within a strict 11-week waterfall schedule by a 5-member student team. The system requires rapid UI delivery for both students and librarians (DG-09, DG-11), enforcement of complex domain rules BR-01 to BR-06 (DG-03), and high unit-testability without UI dependencies (DG-10).

## Decision
Adopt a Modular Monolith built with Python and Django using the Model-View-Template (MVT) pattern combined with  Server-Side Rendering (SSR) and Tailwind CSS. Business logic is strictly isolated into domain service classes decoupled from Django HTTP views.

## Alternatives Considered
1. Decoupled SPA (React/Vue + Django REST Framework): Rejected because maintaining two separate codebases, API serialization layers, and client-side state management doubles development effort and violates the technology constraint favoring SSR (DG-09).

## Consequences
  - Positive: 
  - Accelerates development via Django's built-in ORM, form validation, and admin utilities.
  - Enables fast initial page loads (NFR-02, NFR-04).
  - Simplifies deployment to a single PaaS container.
  - Allows isolated unit testing of service classes via PyTest (DG-10).
  - Negative: 
  - Requires strict code-review discipline (via PRs) to prevent business logic from leaking into Django views or templates.
